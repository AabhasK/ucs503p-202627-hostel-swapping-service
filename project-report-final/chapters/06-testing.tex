\chapter{Testing and Quality Assurance}

\section{Strategy}

Testing works at four levels \cite{pressman2014se}:

\begin{enumerate}
  \item \textbf{Unit tests} of the pure domain: scoring, the matrix, the
  solver, Murty's algorithm, cycles, the Pareto filter, ranking, the
  synthetic generator and the proposal state machine.
  \item \textbf{Scenario tests}: small hand-built hostels with a known
  correct answer (``golden scenarios''), run through the full pipeline.
  \item \textbf{Integration tests} of the API through FastAPI's test
  client, of the data layer, and of the round workflow with the database
  replaced by a stand-in.
  \item \textbf{Manual verification} against a real PostgreSQL database
  (a local PostgreSQL~18 instance and Supabase) and in the browser.
\end{enumerate}

Because the domain imports no framework or database driver, almost all
tests need no infrastructure. The full suite runs in about three seconds
on a laptop.

\subsection{Continuous Integration}

A GitHub Actions workflow installs the package from \texttt{./code} and
runs \texttt{pytest -q} on every push and pull request, on Python 3.10,
3.11 and 3.12, the versions the package declares it supports. Each run
starts a throwaway PostgreSQL, applies the migrations and runs the four
database tests, which are skipped elsewhere and refuse a shared database.
Without migration \texttt{0002} three of them fail, so they guard the
fix in Section~\ref{sec:expiry-defect}. The workflow had listed a branch
named \texttt{develop} rather than \texttt{development}, so pushes to the
team branch never ran CI; this was corrected. A second workflow builds
and publishes the documentation site.

\subsection{Proposals Never Expired}
\label{sec:expiry-defect}

This was the most serious defect, found in November by reading the code
of the approval workflow.

\paragraph{Problem.} A swap chain that one member never answered stayed
open forever, and all its other members were locked out of every other
chain. Members of a chain that had been \emph{executed} were locked out
of every later round as well.

\paragraph{Cause.} Three things combined:
\begin{enumerate}
  \item The domain defined \texttt{expire\_if\_due()}, but no code in the
  workflow or the API called it.
  \item \texttt{rounds.respond()} never compared the reply time with
  \texttt{expires\_at}, so a chain could be approved and executed long
  after its three-day lifetime.
  \item The unique index \texttt{swap\_chain\_members\_one\_live} counted a
  member as live whenever their approval was not \texttt{rejected}. A
  member who had not answered stayed \texttt{pending}, and a member of an
  executed chain stayed \texttt{approved}, so both stayed live forever.
\end{enumerate}

\paragraph{Fix.}
\begin{enumerate}
  \item \texttt{respond()} checks the deadline first. A late reply marks
  the proposal \texttt{expired} and is refused with ``this proposal has
  expired'' (\commit{8e0e196}).
  \item \texttt{offer\_chain()} first runs \texttt{expire\_due\_proposals},
  which marks every overdue proposal expired and frees its members
  (\commit{8e0e196}).
  \item Migration \texttt{0002} adds a \texttt{settled} column to
  \texttt{swap\_chain\_members}, marks the members of already-settled
  proposals as settled, and rebuilds the index over unsettled rows only.
  The workflow sets \texttt{settled} whenever a proposal is executed,
  rejected or expired (\commit{7f1558b}).
\end{enumerate}

\paragraph{Verification.} Three new tests in \texttt{test\_rounds.py}
check that a late accept is refused, that an accept before the deadline
still counts, and that the sweep runs before a new proposal is
inserted; both new tests about deadlines failed before the fix. The
migration and the sweep were also run against a local PostgreSQL~18
database to check three cases: before \texttt{0002} a student from an
executed chain could not join a new one; after it they could, while
being live in two chains at once was still blocked; and the sweep marked
an overdue proposal expired and freed its members.

\paragraph{Lesson.} An invariant enforced by the database has to cover
every way the state machine can end. The index was written when only
rejection was handled, and nobody revisited it when execution and expiry
were added.
